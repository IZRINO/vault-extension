# Ente Auth 文件密码加密 JSON：互通依据

核对日期：2026-11-20。对应本项目[架构 v1.4 §4.5.1–§4.5.3](../../密码管理器浏览器插件-技术架构与选型文档.md#45-全格式导入与导出引擎重点支持密码--passkey--ente-auth)。本项是文件密码加密 JSON **迁入**；§4.5.3 仍只承诺 Ente Auth `.txt` 反向导出，[工单索引](../development-tickets.md)也将加密迁入与 T06 文本往返分开。

## 文件从哪里来

- **Ente Auth 手工文件导出**：`Settings → Data → Export → Encrypted`。用户选择独立文件密码；修改 Ente 登录密码不会改变已有文件。桌面和移动端的手工导出用版本 `1`，文件名形式为 `ente-auth-codes-encrypted-<UTC 时间>.json`。[官方帮助](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/docs/docs/auth/migration/export.md#L8-L24) · [稳定版 writer](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/apps/auth/lib/ui/settings/data/export_widget.dart#L65-L118) · [文件名](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/apps/auth/lib/ui/settings/data/export_widget.dart#L152-L165)
- **本机定时备份**：`Local backup` 设自己的备份密码，手动触发和定时生成的 `ente-auth-manual-backup-*.json` / `ente-auth-daily-backup-*.json` 也走同一个版本和密码学封装；解密内容仍是 URI 行。[官方帮助](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/docs/docs/auth/migration/export.md#L83-L105) · [备份 writer](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/apps/auth/lib/services/local_backup_service.dart#L296-L349)
- **账户云同步、离线数据库不是这种文件**：应用按条目保存 `encryptedData` 和 `header`，使用 Auth 数据密钥；在线模式用账户密钥解包 Auth 密钥，离线模式用系统安全存储保护的本机密钥。不要把单条云数据、数据库、登录密码或应用锁当成文件密码导出。[条目存储](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/mobile/apps/auth/lib/services/authenticator_service.dart#L67-L118) · [密钥分流](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/mobile/apps/auth/lib/services/authenticator_service.dart#L302-L330) · [离线模式说明](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/docs/docs/auth/features/offline-mode.md#L6-L28)
- **官方 Rust CLI**：`ente auth export` 从已登录账户或其已同步本机副本读取，写同一个版本 `1` 文件；`--offline` 不等于能凭一份文本生成文件。独立的 `ente auth decrypt` 不需要账户、CLI vault 或网络。官方库另公开了 `ente_auth::backup::encrypt(plaintext, password)`，可用合成 URI 行直接生成同格式文件，不接触账户。[CLI 文档](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/docs/docs/cli/auth.md#L3-L30) · [CLI 分流](https://github.com/ente/ente/blob/76ccb31acce1beb3a519e73e12c8f0f754e856a1/rust/apps/cli/src/auth/mod.rs#L20-L90) · [独立 writer](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/rust/crates/auth/src/backup.rs#L10-L57)

## 线格式和资源边界

| 部分 | 结论与固定出处 |
| --- | --- |
| JSON 外壳 | 顶层为对象；`version` 是整型 `1`，不是 `"1"` 或 `1.0`；`kdfParams` 含整型 `memLimit`、`opsLimit` 和字符串 `salt`；顶层有 `encryptedData`、`encryptionNonce` 两个字符串。官方 Rust 先校验版本、KDF 与二进制长度，再派生。帮助中的 `4096`、`example_salt` 等只是示意，不能作可解密夹具。[结构与验证](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/rust/crates/auth/src/backup.rs#L10-L85) · [帮助示意](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/docs/docs/auth/migration/export.md#L26-L55) |

| KDF | libsodium `crypto_pwhash` 的 **Argon2id v1.3**（`0x13`，PHC version 19）；`m=memLimit/1024` KiB、`t=opsLimit`、`p=1`，输出 32 B。`memLimit` 在文件里是**字节**；先确认整 KiB 和范围，不截断、溢出或替用户降参。[Dart KDF](https://github.com/ente/ente_crypto_dart/blob/b3f17aac6973b630aff663e4d9f7c6ee92334a62/lib/src/crypto_util.dart#L48-L62) · [Rust 等价参数](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/rust/crates/core/src/crypto/argon.rs#L86-L109) |
| 加密 | `encryptionNonce` 实为 libsodium **`crypto_secretstream_xchacha20poly1305` 的 24 B header**，不拼在 `encryptedData` 里，也不能当作普通 `XChaCha20Poly1305` AEAD nonce 或 XSalsa20 SecretBox nonce。`encryptedData` 是单个认证帧，无 AAD，帧比明文多 **17 B**；初始化后对整段密文只 pull 一次，不按文件加密的 4 MiB 分帧。正常写入 `FINAL`，兼容已认证的历史 `MESSAGE`；无论是否出现 `FINAL`，认证失败都不得进入解析或提交。官方 Rust 用 `crypto_secretstream = 0.2.0`。[Dart 单帧](https://github.com/ente/ente_crypto_dart/blob/b3f17aac6973b630aff663e4d9f7c6ee92334a62/lib/src/crypto_util.dart#L107-L130) · [Rust 单帧兼容](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/rust/crates/core/src/crypto/blob.rs#L18-L55) · [空 AAD](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/rust/crates/core/src/crypto/stream.rs#L53-L95) · [libsodium 线格式常量](https://github.com/jedisct1/libsodium/blob/9511c982fb1d046470a8b42aa36556cdb7da15de/src/libsodium/include/sodium/crypto_secretstream_xchacha20poly1305.h#L17-L52) · [依赖版本](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/rust/crates/core/Cargo.toml#L5-L16) |

原生 Dart writer 默认 `1,073,741,824` 字节 / `4` 次（1 GiB/4）。识别到指定低配 iPhone 才从 `268,435,456` / `16` 开始，派生失败时继续内存减半、次数翻倍，例如 `536,870,912` / `8`、`134,217,728` / `32`、`67,108,864` / `64`；使用成功的原值，不可重新算一组选参。官方 Rust CLI writer 从 256 MiB/16 开始，低到 128 MiB/32 后停止。[稳定版 Dart 依赖](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/packages/ente_crypto_dart_adapter/pubspec.yaml#L8-L15) · [Dart KDF 选参](https://github.com/ente/ente_crypto_dart/blob/b3f17aac6973b630aff663e4d9f7c6ee92334a62/lib/src/crypto_util.dart#L706-L765) · [Dart 低配判断](https://github.com/ente/ente_crypto_dart/blob/b3f17aac6973b630aff663e4d9f7c6ee92334a62/lib/src/models/device_info.dart#L9-L43) · [Rust CLI 选参](https://github.com/ente/ente/blob/76ccb31acce1beb3a519e73e12c8f0f754e856a1/rust/crates/core/src/crypto/argon.rs#L132-L193)

上游 Rust reader 的通用校验是 `memLimit >= 8192`、整 KiB、`opsLimit >= 1`，并且内存 ≤ 4 GiB、`memLimit * opsLimit` ≤ `17,179,869,184`（字节×轮）；这是**上游接受范围，不是浏览器应该承诺的预算**。本项目应在派生前设独立内存/工作量与文件体积上限，给高内存、超限及格式错误返回明确原因。96 MiB 的 KDBX 预算覆盖不了上述常规原生文件；要承诺稳定版 Windows 桌面导出，必须实际量过按需 WASM 的 1 GiB/4（另有 WASM 堆开销）。加密 JSON 还有 Base64 膨胀，不能把明文 URI 大小上限直接当作加密文件上限。[上游验证](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/rust/crates/core/src/crypto/argon.rs#L24-L68) · [KDBX 预算](../release-candidate-status.md) · [二期明文入口](../phase-2-status.md)

## 明文语法、导入器和版本沿革

- **writer 的明文不是 JSON 对象**：手工和 CLI 导出为 UTF-8 的 `otpauth://` 行，手工在每条后写 LF；本机备份清掉空行，解除旧 `toOTPAuthUrlFormat()` 的逐行 JSON 字符串引号后用 LF 连接，不补末尾换行。`otpauth://totp/`、`otpauth://hotp/`（`counter`）、`otpauth://steam/` 复用文本迁移；`codeDisplay` 查询参数内是 JSON（`pinned`、`trashed`、`tags`、`note` 等）。新手工 writer 只跳过损坏的记录，不过滤回收站。现有文本解析的引号、历史 `#` 和算法枚举兼容不应因此丢失。[手工 writer](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/apps/auth/lib/ui/settings/data/export_widget.dart#L211-L221) · [本机备份清洗](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/apps/auth/lib/services/local_backup_service.dart#L296-L313) · [全部条目](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/apps/auth/lib/store/code_store.dart#L69-L125) · [URI 与 metadata](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/apps/auth/lib/models/code.dart#L138-L209) · [OTP 类型](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/apps/auth/lib/models/code.dart#L230-L283) · [显示字段](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/mobile/apps/auth/lib/models/code_display.dart#L65-L119) · [CLI 行格式](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/docs/docs/cli/auth.md#L24-L30) · [CLI 回收站](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/docs/docs/cli/auth.md#L63-L67)
- **reader 能读的比 writer 会写的多**：最新 Rust 导入校验外壳、认证解密、严格 UTF-8，再调用共享文本解析器；除 URI 行，还能处理部分历史逗号分隔以及 `{"items":[{"rawData":…,"display":…}]}` 的富文本 JSON。后者是 reader 的兼容分支，并非此次核对到的手工/本机备份 writer 所写，也不是加密外壳的 v2；仅支持原生加密备份不要求把任意 `items` JSON 识别为备份。密码不符与密文认证失败不可区分，二者都应零写入；结构和预算错误可在提示文件密码前识别。[Rust 导入](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/rust/crates/auth/src/import/mod.rs#L156-L263) · [App 先预检、再请求密码](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/mobile/apps/auth/lib/ui/settings/data/import/encrypted_ente_import.dart#L88-L100)

## 样本与独立验算

**官方可复现来源**：在独立测试环境运行 [Ente Auth 4.4.27 Windows 便携版](https://github.com/ente/ente/releases/tag/auth-v4.4.27)，核对[官方 SHA256SUMS](https://github.com/ente/ente/releases/download/auth-v4.4.27/SHA256SUMS)，首次选 **Use without backups**，从 **Import codes → Plain text** 导入只含合成种子的 TOTP/HOTP/Steam 行，加入置顶、标签、备注和回收站状态，从 **Data → Export → Encrypted** 保存，再用 **Import codes → Ente encrypted export** 导回独立测试环境。无需注册或使用真实账号；部分客户端仍可能检查更新。也可在上游独立库调用 `backup::encrypt` 生成 fixture；上游 CLI 的用例用本机模拟服务演示了无真实账号的导出及独立恢复。[离线模式](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/docs/docs/auth/features/offline-mode.md#L6-L20) · [导入手册](https://github.com/ente/ente/blob/f8a52e5499684c83968f5a63952050758734d0b8/docs/docs/auth/migration/import.md#L36-L50) · [加密往返操作](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/docs/docs/auth/migration/export.md#L8-L16) · [上游模拟用例](https://github.com/ente/ente/blob/9fe7673324181693af512f857c17486d98788c4d/rust/apps/cli/tests/cli/auth.rs#L504-L637)
