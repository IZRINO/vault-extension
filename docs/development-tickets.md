# Vault Extension 剩余开发工单

原始拆分基线为 `4ce8c3d`；2026-11-18 按[架构 v1.4](../密码管理器浏览器插件-技术架构与选型文档.md)、[分期计划](../分期开发与验证计划.md)和[八项决策](spec-gap-review.md)补订。已从 GitHub 读回核对 [38 张工单](https://github.com/IZRINO/vault-extension/issues?q=is%3Aissue%20label%3Aready-for-agent)及 63 条原生阻塞关系，编号 T01–T38 与实际票号对应。以下是待交付的行为，不是通过记录；已实现和待验收的部分见[一期](phase-1-status.md)、[二期](phase-2-status.md)记录。

本轮按维护者要求推进开发、跳过人工签收；最新自动证据、发布候选包和未达项见[候选包验证记录](release-candidate-status.md)。下方依赖和验收阈值不因提前开发而改变。

## 从哪里开始

| --- | --- | --- |

| T08–T20 | WebDAV 同步 | 先做只读连接和本地离线日志，再开放受保护的远端写入。T20 通过前不开发四期。 |

**各票共用的完成标准：** 改动对应的自动回归通过；每期签收同一版本的 Rust、WASM、TypeScript、生产构建及 Edge / Helium 解压安装冒烟。主 WASM 优化后不得超过仓库硬限制 250 KiB（256,000 字节，二期记录是 255,548 字节）；重型按需模块不得挤进解锁和填充路径。禁用 Google 同步/身份服务依赖，不放宽网页权限或信任页面自报来源；未包装密钥、私钥和种子不进页面、持久化明文、错误日志或工单。需要展示或导出单项秘密时沿用现有授权边界，不承诺浏览器能确定性擦除 JS 字符串。

验收只用合成凭证、专用测试账号/目录。注明构建版本、浏览器、样本、命令、观察口径及失败项，不贴原始导出、应用密码、二维码种子或能识别账号的截图。实体设备、真实账号和人工授权不能用 Mock 代签。下文只列**直接前置**；分期准出也是前置，不表示票号必须顺序执行。

## 一期：证明本地库在真实设备上可用

### T01 分开测准并修复后台唤醒与 Popup 首屏 · [#1](https://github.com/IZRINO/vault-extension/issues/1)
前置：无

交付：未超时的库在后台被停止后能迅速恢复；已经锁定或超时的库不会被性能优化重新打开。
- [ ] 分别记录会话恢复到 WASM 可用（`< 5 ms`）及停掉后台后点击 Popup 到首屏可用（`< 50 ms`）。现有 53/52 ms 是 Edge/Helium 停掉后台后发起 `status` 到响应的近似值，不是这两种指标都已测过。
- [ ] 用同一生产包在两浏览器重复冷唤醒，记录样本与波动；超时、系统锁定或会话损坏仍拒绝恢复。不得用预热或改计时起点换取达标。

### T02 用实体 Windows 和原生侧栏签收一期 · [#2](https://github.com/IZRINO/vault-extension/issues/2)
前置：无

交付：用户可以在真实系统解锁、锁屏，并在浏览器实际侧栏管理密码库。
- [ ] 实体 Hello 完成注册、断言和解锁；无 PRF 的设备明确引导用 PIN，不留下不可解的包装。实际锁屏再解锁后，扩展仍锁定；分别记录设备能力与结果，未测的分支不勾选。
- [ ] 在 Edge、Helium 原生侧栏完成增改查、二次验证和复制；检查 30 秒清理及不误删，验证可选 `privacy` 授权、撤回和策略限制。真实 HIBP 联网如验收，只对合成样本逐次同意；未测则单列。
- [ ] 附上本票实机操作和同一构建的通用门禁记录，区分实测与模拟。T01、T02 由最后完成的一票汇总签收；虚拟认证器、窄屏截图不替代实体证据。

## 二期：收尾，不重做填充与验证器

### T03 让 Helium 第一次截图扫码低于 200 ms · [#3](https://github.com/IZRINO/vault-extension/issues/3)
前置：T01、T02

交付：在默认反指纹设置下，用户首次扫描当前网页，就能在目标凭证上看到可保存的正确结果。
- [ ] 固定二期基线（1000×800 视口、420 像素二维码），分别量首次与热扫，记录截图、灰度转换、Worker/WASM 和呈现用时。最近首次 Edge 161 ms、Helium 236 ms；亮/暗样本在 Helium 首次端到端均须 `< 200 ms`，不能只报最快热扫。
- [ ] Edge 不回退；无二维码、取消、切换标签或未获得 `activeTab` 都不误关联。不得关浏览器防护、读网页 canvas 或常驻加载解码器。

### T04 在实际登录流程签收填充、保存和更新 · [#4](https://github.com/IZRINO/vault-extension/issues/4)
前置：T01、T02

交付：用测试账号在两浏览器验证真实多步登录及浏览器原生右键入口，而不只验证本地表单。
- [ ] 在 Google、Microsoft、GitHub 的适用流程核对选中账号、分步填充、保存/改密提示与历史；分别记录真实站点与本地夹具覆盖。需要人工登录、验证或授权时由操作者完成。
- [ ] 回归快捷键、原生右键、受保护条目、OTP 分格及到期切换；无用户动作、隐藏字段和未获确认的跨域帧不释放凭证。记录结果，不采集页面密码。

### T05 在陌生 CSV 上用拖拽或键盘完成字段映射 · [#5](https://github.com/IZRINO/vault-extension/issues/5)
前置：T01、T02

交付：在已有下拉映射基础上补齐计划点名的拖拽交互，键盘用户仍能走完整流程。
- [ ] 拖拽与下拉产生同一映射与预览；必填缺失、同一列重复使用都不能确认。取消、文件替换或预览后改映射不会写入旧结果。
- [ ] 用合成的多行/带引号 CSV 在两浏览器验收；原值不改写，OTP 无法识别时明确提示，全库导出仍须主密码和风险确认。若决定保留下拉作为等效交付，须先在分期计划记录决议，不以“已支持下拉”自动关票。

### T06 用 Bitwarden 和 Ente Auth 原生应用验收往返 · [#6](https://github.com/IZRINO/vault-extension/issues/6)
前置：T01、T02

交付：从真实来源应用导出合成样本，在扩展导入后导回该应用，能继续使用原记录。
- [ ] Bitwarden 明文及密码保护 JSON 验证登录、OTP、卡片、身份和备注；错误文件密码不写入。账号绑定加密文件明确提示重新导出，不承诺仅凭主密码直解。
- [ ] Ente Auth 文本往返核对 TOTP/HOTP/Steam、计数、置顶、标签、备注和回收站；重复导入不推进或降低 HOTP 计数。只保存脱敏的字段对照，不上传导出文件。

### T37 整库导出必须重新验证主密码 · [#37](https://github.com/IZRINO/vault-extension/issues/37)
前置：T01、T02

交付：用户仍可用 PIN 做已获准的日常操作，但要把整个库带到另一环境，必须在导出时重新验证当前库主密码；独立文件密码只用于保护导出文件。
- [ ] 在受信后台对 `.vaultpack`、Bitwarden 明文/密码保护 JSON、Ente 文本和通用 CSV 执行相同的整库授权。仅已解锁、正确 PIN、错误主密码或取消均不交付字节、不生成文件、不清除备份提醒。
- [ ] Edge 和 Helium 上，正确主密码可继续；需要文件密码的格式仍用独立文件密码，明文仍需风险确认。用合成 `.vaultpack` 在新配置恢复凭证；同一 PIN 仍可用于原先允许的单条操作。

### T38 日常看码和网页填码不交付验证码种子 · [#38](https://github.com/IZRINO/vault-extension/issues/38)
前置：T01、T02

交付：用户在 Popup、侧栏或网页填入时仍能取得正确动态码；日常客户端拿不到可持续生成动态码的种子。显式录入、编辑或已授权导出与日常取码分开。
- [ ] 用合成 TOTP、HOTP、Steam 检查日常详情与填充的消息和界面输入：只有授权句柄、动态码和确有必要的时间等信息，不含种子、含种子的设置 URI 或携密完整条目；普通网页不接触种子。
- [ ] 在 Edge/Helium 回归到期切换、受保护条目再次验证、HOTP 先提交计数再交码；写入失败不发码。显式编辑和授权迁移仍工作，锁库后旧句柄不能取码，证据与日志不记录种子。

### T07 用同一生产构建签收二期 · [#7](https://github.com/IZRINO/vault-extension/issues/7)
前置：T03、T04、T05、T06、T37、T38

交付：有可解压安装的版本、可复核的测量与第三方互通记录，可以据此决定是否进入同步开发。
- [ ] Rust、后台、类型、构建、填充、迁移、二期、备份防丢和两浏览器冒烟均通过；确认主核体积、导入器懒加载、密文落盘、来源校验、CSP 和权限没有退化。
- [ ] 报告把自动、人工、性能和格式限制分栏；沿用一期门禁。任何硬指标未过则保持未签收，不以“功能测试全绿”替代。
- [ ] 在同一生产包复验两项修正：整库导出只认当前主密码；日常详情与网页填码只得动态码、不携种子。两项均须通过，原有性能、实体系统、实站和互通门禁不变。

## 三期：两台设备安全同步同一个库

### T08 只读测试 WebDAV 连接，分辨空目录与已有库 · [#8](https://github.com/IZRINO/vault-extension/issues/8)
前置：T07

交付：首屏可选坚果云、Koofr 或自定义 HTTPS 地址，也可继续纯本地使用；测试连接不会写入远端密码库。
- [ ] 在 MV3 无 DOM 环境用 `fetch` 探测，区分空目录、已有 head/snap、残缺库与不可达。保留 Koofr 路径大小写；只允许经强提示开启的回环地址 HTTP 调试。应用用户名和密码仅本机加密保存。
- [ ] 任何 `401/403/429` 立即停请求并显示原因与角标；重启后台不解除熔断，只有用户修正配置、手动测试成功后才恢复。测试期间不发 `PUT`、`DELETE` 或 `LOCK`。
- [ ] 首次手输网盘凭据仅在内存用于本次只读探测，建库或解锁后才加密保存。测试不创建目录或对象；能列目录或收到 `ETag` 不是可写证明。不能证明条件写可靠时只提供读取恢复并说明原因。

### T09 离线编辑和 HOTP 取码后，重启仍有待同步变更 · [#9](https://github.com/IZRINO/vault-extension/issues/9)
前置：T07

交付：改一条记录或取一次 HOTP，即使立即关闭浏览器也不会丢掉本地操作；此票不访问网盘。
- [ ] 将本地密文快照与带共同祖先版本的加密 WAL 同事务提交；写入失败不显示成功、不返回 HOTP。迁移旧 `hotp-snapshot` 只能在新表示持久化后清理，重试不重复取码、不回退计数。
- [ ] 两个设备生成各自的 128-bit 身份和 4 字节随机短码，HLC 在时钟回拨与重启后仍单调；名称、系统、浏览器不进明文文件名。篡改、角色混换或跨库密文均拒绝；旧 `.vaultpack` 继续可读。

### T10 首台在空目录建库，第二台先拉取恢复 · [#10](https://github.com/IZRINO/vault-extension/issues/10)
前置：T08、T09

交付：第一次连接就走对分支：确认为空才建库；已有库先拉取，不另建 DEK；仍可选从本地备份恢复。
- [ ] 刚建的合成库写入所选子目录与 `wal/`，不写供应商根目录。另一端用已有主密码或恢复码重放快照及增量后见到原条目；并发首次建库不得覆盖先成功的一端。
- [ ] 残缺/不可认证、密码错误、两个非空库未确认或远端 `key_epoch` 已变而未重新验证时，不覆盖任一端；保存已知最高 epoch 与认证状态根，遇不连续的旧状态拦截并提示。新装无本地锚点不声称能证明“远端绝对最新”。此步不开放日常自动推送。
- [ ] 已有非空目标库时先用其主密码或恢复码验证；`.vaultpack` 文件密码只能解开凭证备份，不能授予远端身份或认领设备。验证失败或取消保留独立本地库、远端不变。只有已证明可拒绝并发覆盖的空目标才建库；只读服务连目录也不创建。

### T11 阻止空库与未经确认的批量删除污染远端 · [#11](https://github.com/IZRINO/vault-extension/issues/11)
前置：T10

交付：用户清了本地数据或误删一批记录，选择“同步”也不会意外清空云端。
- [ ] 本地有效条目为零且远端非空或本地历史非空，只能拉取恢复，不能推送空 WAL、快照或 head；远端状态未知同样禁止写入。
- [ ] 一次减少 `≥ 50%` 且 `≥ 5 条` 时，暂停推送，仅接受此次删除集合的主密码确认，PIN 不可替代。测试刚好命中、只命中一个阈值、取消、确认后数据再变；拦截时远端字节不变。

### T12 在另一端收到一次离线编辑，而不重传整库 · [#12](https://github.com/IZRINO/vault-extension/issues/12)
前置：T11

交付：Edge 离线保存后重新联网，Helium 能看到变化；重启后台、重放或空轮询不会多改一次。
- [ ] 连续编辑经 2.5 秒防抖追加一个不可变 WAL，按 HLC、随机短码、序号命名；不用 `LOCK`。解锁/打开面板/定时探测只取新对象，普通无变化轮询一次 `Depth: 1`，无凭证对象下载（不把目录响应算作零网络字节）。
- [ ] 模拟上传成功但未确认、后台休眠、断网再连；同一包投递三次状态不变，本机历史不自报冲突；另一端看见的 HOTP 计数不回退。不在此承诺两台离线设备可互斥发放 HOTP。暂不能合并的并发分支须保留且停止覆盖。
- [ ] 在上传前及已送达未确认时分别锁库：锁库后不发任何新 WebDAV 请求（含轮询、重试和清理），不为续传解封网盘密码，密文队列仍在。解锁后先核对已提交进度再续传，每笔只应用一次。

### T13 把无争议的字段合入，只隔离真正冲突 · [#13](https://github.com/IZRINO/vault-extension/issues/13)
前置：T12

交付：一端改备注、另一端改密码，两者都保留；真正有分歧时只暂停对应条目，其他条目照常到达。
- [ ] 基于共同祖先 Base 验证单侧、更改不同条目、同条目不同字段、两侧改成同值均无冲突；同字段异值、改对删、离线同域同账号但密码/2FA 不同，均进加密待裁决区并显示准确角标。
- [ ] 接入两个非空库时先分别验证并预览，区分不同 DEK，不能直接拼密文或把一侧作为空库覆盖；无争议项可合入。锁库/重启不丢待裁决项，未裁决的字段不静默推送。
- [ ] 将备份或独立本地库迁入已验证的目标库：验证来源、预览、显式确认后仅合入条目；目标 DEK、主密码和恢复码不变。错文件密码或取消不修改两端；来源恢复码不能因此打开目标库。
- [ ] 旧设备找不到可验证的共同版本，或不能无损保留新版字段时，停止自动写回、保留本地编辑，升级或显式合并后才续传。用长期离线端和带未知字段的合成记录验证：已删项不复活、新字段及未上传编辑不丢。

### T14 裁决冲突并找回落选的密码 · [#14](https://github.com/IZRINO/vault-extension/issues/14)
前置：T13

交付：用户能看懂哪台电脑改了什么，按全部、单条或字段作出选择，结果同步到另一端。
- [ ] 对照 Base 展示来源设备、时间和字符差异；支持全局/单条选边、保留双份、改删冲突、逐字段挑选及预览微调。取消不改变双方，受保护条目不会因打开对比页就暴露。
- [ ] 密码不同，落选值连同来源与时间进 `passwordHistory[]`，沿用最近 20 条限制；重复应用裁决只记一次。两端重拉后内容一致、已处理角标消失。

### T15 在另一台电脑识别主密码已变更 · [#15](https://github.com/IZRINO/vault-extension/issues/15)
前置：T10

交付：A 修改主密码或用恢复码重置后，B 下次连接能提示输入新主密码，而不是泛称“同步失败”。
- [ ] 经认证的 `key_epoch` 更新只重包 DEK，不重加密整库；旧口令、旧会话或旧设备包装不能绕过重新验证。错误输入不改库，其他端的未上传数据不丢。
- [ ] 新主密码通过后刷新本机可用的 PIN/Hello 包装；不可刷新时明确重新配置，不写半成品。回放旧头不会让旧主密码重新生效。

### T16 重装后认领旧电脑，管理设备清单 · [#16](https://github.com/IZRINO/vault-extension/issues/16)
前置：T12

交付：恢复密码库后可以认领原设备或登记为新设备；设置能查看别名、最近同步时间并移除旧记录。

## 架构与工单范围的差异

Ente Auth 加密 JSON v1 已按架构实现本机导入，三档合成样本及生产包双端回归见[候选记录](release-candidate-status.md#当前候选包-010)。T06 的 Ente Auth、Bitwarden 原生应用往返仍待验收，不以合成样本代签。下表是其余差异，不擅自升级成 T36 的发布门槛。

| 候选项 | 建议从哪里接 | 可独立签收的结果 |
| --- | --- | --- |
| KeePass XML/CSV、1Password CSV、Proton 其他导出/PGP 外层 | 对应的 T28、T29 或 T30 之后 | 每种来源/格式单独用真实工具的合成样本确认方向和载荷，不以 ZIP/JSON 已跑通推断加密包也可用。 |
| FreeOTP+ / WinAuth，RoboForm / Kaspersky，其他供应商 JSON 等 | 分别沿用 T34 / T35 的验收方式 | 每个来源列版本、已映射字段、不能承载的内容和回归样本；Opera 等浏览器方言先复测已有通用 CSV，再决定是否需开发。 |
| 离线“高敏站点缺少 2FA”、开发者凭证到期提醒 | 一期之后 | 分别对一条合成凭证演示提示、修正后消失；已有健康检查和“到期日期”字段不是这两项提醒的验收。 |
| 可选 RS256 | 有实际只支持该算法的 RP 需求时，接 T22 | 独立服务端注册及验签通过；不阻塞计划指定的 ES256、EdDSA。 |
