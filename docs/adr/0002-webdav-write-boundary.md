# 先加入目标库，再决定能否写回网盘

恢复 `.vaultpack` 是取回凭证，不是认领原同步库。连接已有远端库，先以其主密码或恢复码验证，再打开备份、预览并确认迁入；保留远端库身份及恢复码。无法验证远端时，两份数据保持独立。

锁库后停止发起新的同步请求，不因有待传数据而解封网盘密码。本地密文队列保留，解锁后先核对已提交进度再续传；锁库不是撤销已送达网盘的请求。

不能证明 WebDAV 服务能拒绝基于旧版本的条件写时，只支持读取恢复，不建库、不发布新版本、不删除历史。能验证某个快照确实属于同一库，并不能证明可以安全覆盖网盘上另一台设备刚写入的内容。

旧客户端找不到可验证的共同版本，或无法无损保留不认识的字段时，停止自动写回并保留本地编辑。升级或显式合并后才续传；不能仅因旧端离线太久，就舍弃它的改动或用它覆盖新版库。

恢复历史内容不恢复已经用掉的计数。对同一枚 HOTP 或启用递增签名计数的 Passkey，保留各可信记录中的最高计数；无法确认时暂停该凭证，先重新同步或在网站重新登记。默认 `signCount = 0` 的 Passkey 不涉及计数回退。

## #52 加密整包的写入依据

新建目录默认使用整包协议。目录由独占创建的 `pack-root.txt` 认领。它是第一条认证版本记录，包含同一库的主密码和恢复码包装。并发建库时双方暂存的包名各自独立，只有固定根记录的创建者能成为远端库。另一方保留本机原库。旧版 `head.bin` 与 `wal/` 目录仍按上面的增量协议读取和同步。

版本记录的 HMAC 密钥从该库 DEK 单独派生，记录绑定库身份、随机版本 ID、父版本、整包编码、原始密文长度和 SHA-256。轮换主密码时新纪录携带经过认证的新包装。Rust/WASM 用另一把按版本派生的 XChaCha20-Poly1305 密钥认证加密整包，包内另有库身份和版本 ID。按 256 字节填充。凭证快照、未决冲突、删除记录和网站规则在包内，网盘凭据和本机快捷解锁材料仍由本机独立保存。

Koofr 新库用 `packages/p_<id>.json` 保存原始密文的 Base64 封装，其他新库用 `packages/p_<id>.bin` 保存原始密文。库以认证根记录中的格式为准，续传沿用本机待发布记录的格式。加入 JSON 库的设备须使用支持该格式的版本。

发布顺序是将固定字节的包和版本 ID 先存入本机待发布记录，再排他创建该包，完整读回核对长度和哈希，最后排他创建 `versions/v_<id>.txt` 并确认独立可枚举。元数据没有可覆盖的最新版本指针。中断留下的未发布包不参与同步。回执丢失时按同一 ID 核对认证记录，重试复用同一包与记录。已验证端点出现读回完整性错误时恢复只读，保留待发布内容。

写入验证直接在所选同步目录进行，不要求用户另建测试目录。首次确认建库才按需创建目标目录，先暂存并完整读回实际加密包，再在同步目录及其 `packages/`、`versions/` 中用随机临时文件验证：同名创建被拒、两个独立版本都可枚举，只有包而没有版本记录时不能发现新版本。只有全部验证通过才发布 `pack-root.txt`。已有库重新验证前先认证库并校验已有包，只写临时文件；旧增量库继续验证条件更新和删除，不改 `head.bin` 或日志。仅清理本次可核对内容和强 ETag 的探针；不确定归属时保留文件。临时名称不属于正式版本，失败可能留下临时文件或未发布的加密包，不会建成远端库或覆盖现有正式文件。

客户端记住已认证的版本，缺失或替换时停止应用或写入。目录有新记录才下载必要整包，浏览器持续前台时每五分钟检查，编辑只提交本机密文。合并必须取可信共同版本。历史只展示最近五个已合并版本，远端保留版本记录和可能被离线设备需要的包，不自动回收；索引有读入上限。未知数据、无法验证的共同版本或达到读取上限时，保留本机修改并提示处理。

**v0.2.1 的协议区别**：旧增量库更新同一个 `head.bin`，必须能拒绝过期条件写。整包库不更新共享指针；若同名条件创建不可靠，只有在目标目录另行证明「临时名写入并完整读回 → `MOVE` 且 `Overwrite: F` 排他发布」能拒绝替换、原目标读回不变、各分支仍可独立枚举时，才能用这条路径。它不授权覆盖或删除已有正式对象；旧端不认识此写法仍须只读。Koofr 的一次 `412` 或完整 JSON 读回只证明了一个步骤，不是建库验收。失败分类与脱敏诊断只解释停止原因，不更改写入判据。见 [v0.2.1 发布说明](../releases/v0.2.1.md)与[分版本验收记录](../agents/whole-pack-webdav.md)。
