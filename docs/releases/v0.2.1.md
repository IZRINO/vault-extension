Vault 0.2.1 让 Koofr 上的新建整包库在条件删除不可用时仍能写入。适用于 Microsoft Edge 和 Helium。

### 同步

- 上传前仍先读取远程版本。没有分叉就只拉取；两边都有修改就合并，再发布一个新版本文件，不覆盖另一台设备已经发布的文件。
- Koofr 不遵守 `If-Match` 和 `If-None-Match`。v0.2.0 因此会在发布远端库之前停止写入。本版不再把这一点当成整包库只读的理由。
- 新文件先写到临时名，读回一致后用 `MOVE` 且 `Overwrite: F` 放到正式名。目标已存在时返回 412，正式文件保持不变。
- v0.2.0 不认识这种写入方式。本版保存的连接对 v0.2.0 仍是只读，避免旧版用条件 PUT 覆盖 Koofr 上的文件。升级后请重新加载扩展，并在设置里重新验证写入。
- 同步目录里如果已有不符合整包命名的文件，建库仍会拒绝。探测留下的 `packages/target.txt` 和 `packages/tmp_b.txt` 需要先删除，或改用一个空目录。

### 安装与升级

1. 下载附件 `Vault-0.2.1-chrome-mv3.zip`。可运行 `Get-FileHash .\Vault-0.2.1-chrome-mv3.zip -Algorithm SHA256`，与 `SHA256SUMS.txt` 核对。
2. 首次安装时，将 ZIP 解压到固定目录，在 `edge://extensions` 或 Helium 的 `chrome://extensions` 开启开发者模式，选择「加载解压缩的扩展」，选中含 `manifest.json` 的目录。
3. 从 v0.2.0 升级时，先导出加密 `.vaultpack` 备份，保留已安装的扩展。将新版解压到原安装目录，再点击「重新加载」。同一同步库的设备请一起升级。
4. 已有 WebDAV 增量库继续使用原协议。试用整包同步时，请选择新的专用目录，在目标库预览并确认要迁入的凭证。
